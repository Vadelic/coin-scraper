# Требования к skills каталогов монет

Единый стандарт для `skills/coin-catalog-{slug}/SKILL.md`. Эталонная реализация — [skills/coin-catalog-sberbank/SKILL.md](../skills/coin-catalog-sberbank/SKILL.md).

Контракт JSON tool — [coin-catalog-scraper-requirements.md](coin-catalog-scraper-requirements.md) и `coins_catalog.schema.json`.

---

## 1. Назначение

| Требование | Описание |
|------------|----------|
| Один skill — один банк | Skill ↔ tool `coin-catalog-{slug}` |
| Только актуальные данные | Цены и состав — из stdout tool, не из памяти модели и не с диска |
| Единый JSON | Один объект из stdout; stderr не парсить |
| Статус сбора | При `scrape_status` ≠ `ok` — статус + `error`, **без** таблиц цен |

---

## 2. Frontmatter

```yaml
---
name: coin-catalog-{slug}
description: Каталог монет {Банк} ({домен}): поиск, цены, группировка по названию, сортировка по металлу и весу. … Use when user asks about …
disable-model-invocation: true
---
```

- `name` совпадает с именем tool.
- `description`: WHAT (каталог, поиск, цены, группировка) + WHEN (триггеры RU/EN) + `investment_only` по умолчанию (если применимо).
- `disable-model-invocation: true` — skill только по явному вызову.

---

## 3. Обязательные разделы SKILL.md

1. **Когда использовать** — сценарии + строка «Результат для пользователя» (группировка, сортировка, таблицы).
2. **Порядок действий** — вызов tool → JSON → `scrape_status` → фильтр → группировка → сортировка и таблицы.
3. **Группировка по названию** — общий алгоритм (§4).
4. **Сортировка и формат вывода** — общие правила (§5).
5. **Поиск монеты** — `query`, фильтр, группировка, таблицы.
6. **Правила устойчивости** — маппинг цен API, `investment_only`, ошибки.
7. **Важные пути** — `Tool: coin-catalog-{slug}`.

Раздел «Сводка и аналитика» в skill **не** выделять: сводка использует тот же сгруппированный вывод; при необходимости добавить кратко `scrape_status`, `total_coins`, `query`, `investment_only` перед таблицами.

---

## 4. Группировка по названию (общая)

Применять ко **всем** спискам `coins[]` после фильтрации.

1. **Нормализация:** lower case; схлопнуть пробелы; убрать кавычки, лишние дефисы/скобки; обрезать «инвестиционная монета», год `20xx`, дубли веса/металла в имени.
2. **Жёсткое объединение:** одинаковый ненулевой `catalog_number` → одна группа.
3. **Похожие названия:** совпадение нормализованных имён **или** вхождение **или** общая подстрока ≥ 8 символов.
4. **Fallback:** `metal` + `weight_g` совпали, имена только похожи → одна группа.
5. **Конфликты:** несколько групп-кандидатов → блок «неоднозначные», без угадывания.
6. **Заголовок группы:** самое полное `name` (при равенстве — наиболее частое).

---

## 5. Сортировка и формат вывода (общие)

**Сортировка:**

1. Группы по `metal`: `Золото` → `Серебро` → `Платина` → остальные (алфавит) → «нет данных».
2. Внутри металла — по минимальному `weight_g` в группе (возрастание; `null` в конце).
3. Строки в группе — `metal`, затем `weight_g`.

**Таблица на группу** (`### {заголовок}`):

| Металл | Вес, г | Продажа, ₽ | Выкуп, ₽ |
|--------|--------|------------|----------|

- `catalog_number` в таблице **не** показывать.
- `null` → «нет данных».
- «Неоднозначные» — без группировки.

---

## 6. Параметры tool

| Параметр | По умолчанию |
|----------|----------------|
| `investment_only` | Всегда, если банк поддерживает и пользователь не просил весь каталог |
| `query` | При узком поиске |
| Исключение | «Весь каталог», памятные, «все монеты» → без `investment_only` |

Банк-специфика (`availability`, `region`, фильтр страны и т.д.) — только в «Порядок действий» и «Правила устойчивости» конкретного skill.
