# Золотая плата Coin Catalog

## Когда использовать

- Нужен каталог монет банка Золотая плата (goldenplata.ru).
- Нужно **найти монету** в этом банке (по названию, артикулу, металлу, весу, цене и т.п.).
- Нужна сводка или аналитика по каталогу Золотой платы.

Данные только из tool `coin-catalog-goldenplata`, не из памяти модели.

## Порядок действий

1. Вызвать `coin-catalog-goldenplata`.
   - **По умолчанию всегда** передавать `investment_only` (`--investment-only`) — раздел [российских инвестиционных монет](https://goldenplata.ru/catalog/investitsionnye-monety/rossiyskiye/).
   - **Исключение:** пользователь явно просит **весь** каталог, памятные/коллекционные монеты или «все монеты» — тогда `investment_only` **не** передавать (общий каталог `/catalog/`).
   - Поиск на витрине — параметр `query` (URL `?q=…` на странице каталога): ключевые слова из запроса; сочетается с `investment_only`.
2. Распарсить единственный JSON из stdout (stderr — логи, не парсить).
3. Если `scrape_status` ≠ `ok` — сообщить статус и текст `error`, не выдавать цены как актуальные.
4. Дальше — поиск монеты и/или сводка (см. ниже).

## Поиск монеты

1. Сформировать `query` из запроса: название («Георгий Победоносец»), металл («золото»), артикул (`7872`) и т.д.
2. Вызвать tool с `investment_only`, если не запрошен полный каталог; с `query`, если поиск узкий.
3. В `coins[]` оставить записи по смыслу: `name`, `catalog_number`, `metal`, `weight_g`, `buy_price`, `sell_price`.
4. Пользователю: для каждой подходящей монеты — `name`, `catalog_number`, `metal`, `weight_g`, `buy_price`, `sell_price` (₽; `null` → «нет данных»).
5. Если совпадений нет — «не найдено» + что искали; при необходимости другой `query` или уточнение у пользователя.

## Сводка и аналитика

При запросе на обзор каталога:

- банк: Золотая плата, `scrape_status`, `total_coins`, при наличии — `query`, `investment_only`;
- min/max `buy_price`, min/max и медиана `sell_price` по валидным значениям;
- топ по `metal`;
- доля пропусков в `name`, `buy_price`, `sell_price`, `metal`.

## Правила устойчивости

- Не читать JSON-файлы на диске — только stdout tool.
- Числа цен брать из JSON; при обработке строк — убрать ₽ и пробелы.
- Отсутствующее поле — «нет данных».
- Пустой `coins` или ошибка сбора — ответ без падения, с объяснением.
- Не вызывать tool без `investment_only`, если пользователь не просил явно весь каталог.
