# АТБ Coin Catalog

## Когда использовать

- Нужен каталог монет банка АТБ (atb.su).
- Нужно **найти монету** и **цены** в этом банке (по названию, артикулу, металлу, весу и т.п.).
- Нужна сводка или аналитика по каталогу АТБ.

Данные только из tool `coin-catalog-atb`, не из памяти модели.

**Результат для пользователя:** вызов tool → обработка `coins[]` → **всегда** сгруппированный вывод (поиск, полный каталог, сводка): монеты с похожими названиями в одной группе, сортировка по металлу и весу, цены продажи и выкупа.

## Порядок действий

1. Вызвать `coin-catalog-atb`.
   - **По умолчанию всегда** передавать `investment_only` (`--investment-only`, AJAX `category=479`) — только инвестиционные монеты.
   - **Исключение:** пользователь явно просит **весь** каталог, памятные/коллекционные монеты или «все монеты» — тогда `investment_only` **не** передавать.
   - Поиск на сайте — параметр `query` (поле `name` в AJAX POST): ключевые слова из запроса (сочетается с `investment_only`).
   - **Цена продажи** (`sell_price`) — с карточки витрины.
   - **Цена выкупа** (`buy_price`) — на atb.su не публикуется; в JSON всегда `null` («нет данных»).
2. Распарсить единственный JSON из stdout (stderr — логи, не парсить).
3. Если `scrape_status` ≠ `ok` — сообщить статус и текст `error`, не выдавать цены как актуальные (без таблиц цен).
4. Отфильтровать `coins[]` по смыслу запроса (если нужен узкий поиск).
5. **Сгруппировать** по названию (см. ниже).
6. **Отсортировать** и вывести таблицами с ценами (см. ниже).

## Группировка по названию

Применять ко **всем** спискам монет из tool после фильтрации.

1. **Нормализация названия** (ключ группировки): нижний регистр; схлопнуть пробелы; убрать кавычки, лишние дефисы и скобки; обрезать хвосты «инвестиционная монета», год `20xx`, суффиксы с весом/металлом, если они дублируют поля `metal` / `weight_g`.
2. **Жёсткое объединение:** одинаковый ненулевой `catalog_number` → одна группа.
3. **Похожие названия:** две записи в одну группу, если нормализованные имена совпадают **или** одно содержит другое **или** есть общая значимая подстрока ≥ 8 символов.
4. **Fallback:** если `metal` и `weight_g` совпали, а имена только похожи (не дословно) — одна группа.
5. **Конфликты:** если монета подходит к нескольким группам — не угадывать; вынести в блок «неоднозначные» с перечислением кандидатов.
6. **Заголовок группы:** самое полное `name` среди вариантов (при равенстве — наиболее частое).

## Сортировка и формат вывода

**Сортировка (всегда):**

1. **Группы** — по `metal`: `Золото` → `Серебро` → `Платина` → остальные (алфавит) → «нет данных».
2. Внутри одного металла — по **минимальному** `weight_g` в группе (по возрастанию; `null` в конце).
3. **Строки внутри группы** — снова `metal` (если в группе разные), затем `weight_g` по возрастанию.

**Формат ответа:**

- На каждую группу — заголовок `### {заголовок группы}` и таблица:

| Металл | Вес, г | Продажа, ₽ | Выкуп, ₽ |
|--------|--------|------------|----------|
| `metal` | `weight_g` | `sell_price` | `buy_price` |

- Артикул (`catalog_number`) в таблице **не выводить**; использовать только при группировке, поиске и фильтрации.
- Цены — числа из JSON; `null` → «нет данных» (для АТБ колонка выкупа обычно «нет данных»).
- Если в группе одна строка — тот же формат (таблица из одной строки).
- Блок «неоднозначные» — выводить без группировки.
- При сводке каталога — перед таблицами кратко: `scrape_status`, `total_coins`, при наличии — `query`, `investment_only`.

## Поиск монеты

1. Сформировать `query` из запроса: название («Георгий Победоносец», «червонец»), металл («золото»), артикул (`5111-0178`) и т.д.
2. Вызвать tool с `investment_only`, если не запрошен полный каталог; с `query`, если поиск узкий; для обзора — без `query`, затем отфильтровать локально по `coins[]`.
3. В `coins[]` оставить записи по смыслу запроса: `name`, `catalog_number`, `metal`, `weight_g`, `buy_price`, `sell_price`.
4. **Сгруппировать** (секция «Группировка по названию»).
5. **Отсортировать** и вывести таблицами с ценами (секция «Сортировка и формат вывода»).
6. Если совпадений нет — «не найдено» + что искали; при необходимости другой `query`.

## Правила устойчивости

- Не читать JSON-файлы на диске — только stdout tool.
- Числа цен брать из JSON; при обработке строк — убрать ₽ и пробелы.
- Отсутствующее поле — «нет данных».
- Пустой `coins` или ошибка сбора — ответ без падения, с объяснением.
- Не вызывать tool без `investment_only`, если пользователь не просил явно весь каталог.
