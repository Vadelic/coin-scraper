# Coin Price Analytics

## Когда использовать
- Когда нужно сравнить цены инвестиционных монет других банков с монетами Сбера.
- Когда нужно найти монеты, совпадающие со Сбером, во всех банках или только в выбранных.
- Когда нужен табличный ответ с обязательной ценой продажи и отдельной ценой выкупа (если есть).

## Банковские скиллы для получения данных
- `coin-catalog-sberbank` (база сравнения, вызывать всегда).
- `coin-catalog-atb`
- `coin-catalog-aurumex`
- `coin-catalog-goldenplata`
- `coin-catalog-zoloto-md`
- `coin-catalog-vtb`

## Порядок действий
1. Определить охват банков:
   - если пользователь перечислил банки, сравнивать только с ними;
   - если банки не указаны, по умолчанию сравнивать Сбер со всеми доступными банками.
2. Получить данные Сбера через `coin-catalog-sberbank`.
3. Получить данные остальных банков через соответствующие банковские скиллы.
4. Использовать только результаты банковских скиллов:
   - не вызывать tools напрямую;
   - не читать файлы напрямую.
5. Оставить в сравнении только инвестиционные монеты.
6. Сопоставить монеты других банков с монетами Сбера по строгому алгоритму.
7. Сформировать ответ блоками по монетам в фиксированном формате.

## Алгоритм сопоставления (строго)
- Шаг 1 (приоритет): match по `article/code` после нормализации.
- Шаг 2 (fallback): если артикул отсутствует у одной из сторон, match по `normalized_name + normalized_weight + normalized_metal`.
- Шаг 3: если кандидат совпадения не единственный, не выбирать автоматически и переносить запись в блок неоднозначных.
- Нормализация названия: нижний регистр, убрать двойные пробелы, служебные символы и лишние разделители.

## Политика конфликтов
- Артикул/код всегда приоритетнее текстовых полей.
- Если `name + weight` совпали, а `metal` расходится, считать монету несовпавшей.
- Если найдено несколько кандидатов в одном банке, помечать как `неоднозначное совпадение` и не включать в основной блок сравнения.
- Запрещено «угадывать» совпадения вручную.

## Что возвращать пользователю
- Единица вывода: один блок на одну монету Сбера.
- Заголовок блока в строку Жирный:
  - `Артикул` (если есть);
  - `Название монеты`;
  - `Номинал` (если есть).
  - `Ссылка url`.
- Под заголовком двухколоночный формат:
  - левая колонка: цена сбера;
  - правая колонка: построчно `Банк -> Цена продажи` для этой же монеты.
- Ниже отдельный блок выкупа: построчно `Банк -> Цена выкупа` только где выкуп есть.

- Дополнительно в конце: краткая сводка совпадений по банкам и список неоднозначных совпадений.

## Правила устойчивости
- Числовые цены нормализовать (убрать валютные символы, пробелы и нечисловые хвосты).
- При отсутствии любого поля выводить `нет данных`.
- Если цена выкупа отсутствует, показывать `нет данных` в отдельной ячейке выкупа.
- Если URL отсутствует, показывать `нет ссылки`.
- Если совпадений со Сбером нет, вернуть пустой результат и пояснение без ошибки.
- Если один или несколько банков недоступны, вернуть частичный результат и явно перечислить недоступные банки.

## Минимальные проверки перед ответом
- В каждом блоке монеты есть исходная запись Сбера.
- В ценовом сравнении Сбер всегда отображается в левой колонке.
- Для всех банков в правой колонке цена продажи заполнена значением или `нет данных`.
- Банки в результате соответствуют пользовательскому scope (или all-by-default, если scope не указан).
