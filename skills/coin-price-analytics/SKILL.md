# Coin Price Analytics

## Когда использовать

- Нужно **сравнить цены** на инвестиционные монеты **у разных банков**.
- Нужно понять, у какого банка цена **ниже или выше**, чем у **Сбербанка** (база сравнения).
- Нужен ответ с **выводами** (занижена / завышена / на уровне рынка) и **таблицей** по сопоставленным монетам.
- Пользователь просит сравнить конкретные монеты, весь инвестиционный каталог или выбранный набор банков.

**Не использовать** для каталога одного банка без сравнения — для этого банковые скиллы `coin-catalog-*`.

## Источник данных

Данные **только** через банковые скиллы (не tools напрямую, не JSON с диска, не память модели).

| Банк | Skill |
|------|-------|
| Сбербанк (эталон) | `coin-catalog-sberbank` |
| АТБ | `coin-catalog-atb` |
| Aurumex | `coin-catalog-aurumex` |
| Golden Plata | `coin-catalog-goldenplata` |
| Lanta | `coin-catalog-lanta` |
| РСХБ | `coin-catalog-rshb` |
| ВТБ | `coin-catalog-vtb` |
| Zoloto MD | `coin-catalog-zoloto-md` |

## Порядок действий

1. **Охват банков**
   - Если пользователь назвал банки — сравнивать только их + Сбер (всегда).
   - Если банки не указаны — Сбер + **все** скиллы из таблицы выше.
   - Если запрос узкий (конкретная монета, металл, вес) — передать тот же смысл в банковские скиллы (`query` / фильтр по `coins[]` по правилам каждого скилла).
2. **Сбор данных** — последовательно вызвать нужные скиллы:
   - сначала `coin-catalog-sberbank` (база);
   - затем остальные банки из охвата.
   - В каждом скилле по умолчанию `investment_only`, если пользователь не просил весь каталог.
   - Если `scrape_status` ≠ `ok` у банка — зафиксировать ошибку; для этого банка в таблице ставить «нет данных», сравнение по нему не строить.
3. **Сопоставление монет** между банками (см. ниже). Каждая строка анализа привязана к **одной монете Сбера** (или группе эквивалентов Сбера).
4. **Сравнение цен** — для каждой сопоставленной пары/группы сравнить `sell_price` (обязательно) и `buy_price` (если есть у обеих сторон) с ценой Сбера.
5. **Выводы** — текстом по банкам и/или по монетам: занижена, завышена, на уровне Сбера; указать величину отклонения в ₽ и %.
6. **Таблица** — сводная таблица по всем проанализированным монетам (шаблон ниже). Выводы должны опираться на неё.

## Алгоритм сопоставления (строго)

Сопоставлять **одинаковые или похожие** монеты. Логика согласована с группировкой в `coin-catalog-*`:

1. **Нормализация названия:** нижний регистр; схлопнуть пробелы; убрать кавычки, лишние дефисы/скобки; обрезать «инвестиционная монета», год `20xx`, дубли веса/металла в имени.
2. **Приоритет:** одинаковый ненулевой `catalog_number` → одна монета.
3. **Похожие названия:** нормализованные имена совпадают **или** вхождение **или** общая подстрока ≥ 8 символов.
4. **Fallback:** `metal` + `weight_g` совпали, имена только похожи → одна монета.
5. **Конфликты:** несколько кандидатов в одном банке → **не угадывать**; вынести в блок «неоднозначные совпадения» с перечислением кандидатов и цен.
6. **Расхождение металла:** при совпадении `name` + `weight_g`, но разном `metal` — **не** считать одной монетой.

## Сравнение с Сбербанком

- **Эталон:** цена продажи и (если есть) выкупа Сбера по сопоставленной монете.
- **Продажа (`sell_price`):** основа выводов «дешевле / дороже Сбера».
  - ниже Сбера → **занижена** (выгоднее покупателю, чем в Сбере);
  - выше Сбера → **завышена**;
  - разница ≤ 0,5% от цены Сбера → **на уровне Сбера** (указать в таблице без яркой оценки).
- **Выкуп (`buy_price`):** если есть у Сбера и у банка — отдельная колонка и краткий комментарий (выше выкуп Сбера у банка → банк платит больше при сдаче и т.д.).
- **Отклонение:** `Δ ₽ = цена_банка − цена_сбера`, `Δ % = Δ / цена_сбера × 100` (округление до 1 знака после запятой для %).
- Числа нормализовать: убрать символы валюты, пробелы-разделители, нечисловые хвосты.

## Формат ответа пользователю

### 1. Краткое резюме

2–5 предложений: сколько монет сопоставлено, какие банки дешевле/дороже Сбера в среднем по выборке, есть ли систематическое занижение/завышение. Упомянуть банки с ошибкой сбора, если были.

### 2. Сводная таблица (обязательно)

Одна таблица на весь анализ (при большом числе монет — разбить по металлу, сохранив те же колонки).

| Монета | Металл | Вес, г | Сбер продажа | Сбер выкуп | {Банк} продажа | Δ к Сберу | Оценка |
|--------|--------|--------|--------------|------------|----------------|-----------|--------|

- **Монета** — заголовок группы (самое полное `name`); при наличии — `catalog_number` в скобках после названия.
- **{Банк} продажа** — отдельная колонка на каждый банк из охвата (кроме Сбера); `null` → «нет данных».
- **Δ к Сберу** — для каждого банка: `+1 234 ₽ (+2,3%)` или `−500 ₽ (−0,8%)` относительно продажи Сбера.
- **Оценка** — кратко: «занижена», «завышена», «на уровне», «нет пары», «неоднозначно».
- Строки сортировать: металл (Золото → Серебро → …), затем вес по возрастанию, затем название.

Допустимо дублировать детализацию **по одной монете** (блок с URL Сбера и построчным списком банков по возрастанию цены продажи со стрелками ↑/↓ к Сберу), если пользователь просил подробный разбор — но **таблица и резюме обязательны всегда**.

### 3. Неоднозначные совпадения

Отдельный список, если есть: монета Сбера, банк, кандидаты с ценами, почему не выбран автоматический match.

## Правила устойчивости

- Сбер в таблице и в расчёте Δ **всегда** присутствует как эталон.
- Не сравнивать цены банка, для которого нет сопоставленной монеты Сбера (или наоборот) — строка «нет пары».
- Если совпадений со Сбером нет — сообщить без ошибки, таблицу не выдумывать.
- Частичный сбой банка — остальные банки в таблице; в резюме перечислить недоступные.
- URL монеты Сбера — в резюме или в сноске к строке, если есть в JSON; иначе «нет ссылки».

## Минимальные проверки перед ответом

- [ ] Данные получены через банковые скиллы, не через прямой вызов tools.
- [ ] Сбер вызван и использован как база сравнения.
- [ ] Есть текстовые **выводы** (занижена / завышена / на уровне) с опорой на цифры.
- [ ] Есть **сводная таблица** по всем проанализированным сопоставлениям.
- [ ] Охват банков соответствует запросу пользователя (или all-by-default).
- [ ] Неоднозначные match не слиты в одну строку без пометки.
